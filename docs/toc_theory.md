# Theory of Computation (TOC) Mapping & Concepts

This document outlines how each component of the CodeSnap compiler demonstrates foundational concepts from the Computer Science & Engineering **Theory of Computation** curriculum.

---

## 1. The Chomsky Hierarchy

The Chomsky Hierarchy classifies formal grammars and languages into four levels of expressive power:

| Level | Language Class | CodeSnap Application | Theoretical Automaton |
| :---: | :--- | :--- | :--- |
| **Type 3** | **Regular Languages** | Lexical tokens (Identifiers, Numbers, Keywords, Strings, Operators) | Deterministic Finite Automaton (DFA) / NFA |
| **Type 2** | **Context-Free Languages** | Nested statements (`IF/ELSE`, `WHILE`, `FOR`), expressions with matching parentheses | Pushdown Automaton (PDA) / Recursive Descent Parser |
| **Type 1** | **Context-Sensitive Languages** | Semantic analysis (Variable declaration before use, type consistency, scope resolution) | Linear Bounded Automaton (LBA) |
| **Type 0** | **Recursively Enumerable** | Program Execution / Interpretation (Arbitrary while loops, computation) | Turing Machine |

## 2. Regular Expressions and Deterministic Finite Automata (DFA)

During Lexical Analysis (Phase 1), source code is partitioned into tokens. In formal theory, each token type forms a **Regular Language**:

### A. Identifier Language
$$L_{\text{Ident}} = \{ w \in \Sigma^* \mid w = [a\text{-}zA\text{-}Z\_][a\text{-}zA\text{-}Z0\text{-}9\_]^* \}$$

Recognized by DFA $M_1 = (Q, \Sigma, \delta, q_0, F)$:
- $Q = \{ q_0, q_1, q_{\text{trap}} \}$
- $\Sigma = \{ [a\text{-}zA\text{-}Z\_], [0\text{-}9], \text{other} \}$
- $q_0$: Start state
- $F = \{ q_1 \}$ (Accepting state)
- $\delta(q_0, [a\text{-}zA\text{-}Z\_]) = q_1$
- $\delta(q_1, [a\text{-}zA\text{-}Z0\text{-}9\_]) = q_1$

### B. Numeric Literal Language
$$L_{\text{Num}} = \{ w \in \Sigma^* \mid w \in \text{Digits}^+ \cup (\text{Digits}^+ \cdot '.' \cdot \text{Digits}^+) \}$$

Recognized by DFA $M_2$:
- $Q = \{ q_0, q_1, q_2, q_3, q_{\text{trap}} \}$
- $F = \{ q_1, q_3 \}$ where $q_1$ accepts integers and $q_3$ accepts floating-point literals.

## 3. Context-Free Grammars and Pushdown Automata

Lexical analysis cannot verify structural nesting (e.g. matching `START` and `STOP`, matching parentheses `( ... )`, nested `IF ... END` blocks). This limitation arises because Finite Automata possess finite memory and cannot count arbitrarily deep nestings (as proven by the **Pumping Lemma for Regular Languages**).

Syntax Analysis (Phase 2) therefore uses a **Context-Free Grammar (CFG)**:
$$G = (V, \Sigma, R, S)$$

A **Recursive Descent Parser** represents the deterministic implementation of a **Pushdown Automaton (PDA)**, where the program call stack serves as the infinite pushdown store.

---

## 4. Context-Sensitivity & Semantic Analysis

Context-Free Grammars cannot enforce constraints such as:
1. "A variable must be declared with `LET` before being referenced."
2. "The operands of an arithmetic operator must be numeric."

These constraints are **Context-Sensitive** (equivalent to languages like $\{ a^n b^n c^n \mid n \ge 1 \}$ which cannot be generated by a CFG).
Phase 3 (Semantic Analyzer) resolves this by using an auxiliary memory structure: the **Symbol Table**.

---

## 5. Turing Completeness & The Halting Problem

CodeSnap supports conditional jumps and unbounded loops (`WHILE` statements), making the language **Turing-complete**.

According to **Alan Turing's Halting Problem theorem (1936)**, it is undecidable to determine statically whether an arbitrary program will terminate or loop infinitely.
To maintain system safety without compromising user experience, the CodeSnap interpreter applies **bounded step execution** (terminating with an informative warning if step count exceeds 50,000).
